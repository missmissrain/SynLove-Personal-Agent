# 执行内核的 Windows 桌面能力

后台执行内核通过 Windows MCP 访问桌面，主人格仍负责对话与任务委派。执行内核同时加载后台任务控制器，可查询、读取和停止后台命令。

## 部署

Windows MCP 需要 Python 3.12 或更高版本。本项目验证的版本为 `windows-mcp 0.8.5`；应在独立环境中安装该版本及其依赖，不覆盖模型服务环境。

将 `config/windowsMcpConfig.example.json` 复制为 `config/windowsMcpConfig.json`，填写独立随机密钥及该环境的 Python 路径，再启用配置。私有文件不得提交仓库。默认接口为回环地址的 `17865/mcp`，工具调用超时为 120 秒；端口冲突时同时修改服务端与客户端配置。

使用登录用户的交互式计划任务启动 `plugins/windows/WindowsDesktopService.py`。任务应使用 `pythonw.exe`，工作目录为项目根目录，触发器为用户登录。启动前确认已有桌面会话，避免重复启动服务。

桌面服务必须运行在实际登录的用户会话中。以 SYSTEM 运行的 Agent 可以通过鉴权接口调用它，但不能在 Session 0 中启动桌面工具来代替交互桌面。用户注销后不保证桌面可操作，锁屏状态也可能限制操作。

## 接口与验收

接口采用 MCP Streamable HTTP，使用独立 Bearer 密钥。普通 HTTP 仅允许回环地址；跨设备部署必须使用 HTTPS。密钥通过环境变量交给服务，不放入进程命令行。

启用后，执行内核挂载服务完整工具列表。内核启动时检查桌面快照、点击、输入、滚动和快捷键，以及后台任务的列表、输出和停止工具；连接失败必须明确报告能力不可用。每次操作应先读取快照，再操作并复核结果。

此接口控制的是运行该桌面服务的电脑。其他终端仍通过设备列表及远控通道定位，不能将服务器桌面误当成目标终端。

可使用 `node --test tests/WorkerDesktopTests.mjs` 校验配置边界。正式部署还应验证匿名请求被拒、鉴权后的工具列表与桌面快照，以及执行内核实际挂载的工具；配置检查不能替代真实协议验收。

升级既有实例时，还需核对 `DSH_HOME/.agent-presets/task-worker/agent.cordis.yml`。运行目录中的用户预设可能优先于仓库配置；先备份、比较其中的自定义修改，再将本次执行预设更新合并到实际加载文件。启动日志的 `roles.checked` 记录才是本轮实际工具装配结果。
