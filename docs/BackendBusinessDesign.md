# 后台业务边界

四项功能的实现归 `SynLove-Backend-Service/businessRuntime`：

- 爬虫中心：RSSHub和网页来源采集、新闻去重、Gemma摘要、每日新闻日程。
- 网页收集：隔离浏览器提取网页，由配置的Gemma接口整理。
- 视频理解：文件/链接输入、音频转写、抽帧、画面说明、报告。
- 定时任务：一次性及每日提醒，到期结果持久入队。

个人实例负责对话、个人历史和记忆、QQ/微信连接、个人消息队列、编码连接器及本机观测。远端只维护自身业务执行记录，不保存个人消息平台凭据。

旧 `digest/crawler/video/reminders` ID 和MCP工具名保持兼容。新安装通过 `implementation=backend` 在本机调用配套Backend实现；远端通过 `transport=relay` 和固定能力名调用。原生产兼容实现暂留，直到旧数据迁移与远端验收通过；此次不会提前删除正在使用的代码。

## 调用与结果

普通请求：个人MCP桥 → 固定HTTP或VPS任务API → 出站业务节点 → 对应业务服务。写请求使用稳定requestId，长任务只轮询同一操作，不因网络超时自动重新执行。

后台通知：远端SQLite发件箱 → 本机接收器持久落盘 → 远端确认 → 既有QQ队列按稳定ID去重 → 原QQ连接器发送。网络不通时保留结果；发送受平台限制，不声称平台级恰好一次投递。

本版一个业务部署服务一个个人实例。若要共享同一部署给多个用户，需要额外的租户身份、数据库隔离和能力路由，不可直接共用当前日程与通知库。

## 迁移顺序

先准备服务器代码和依赖，再冻结本机旧调度、导出提醒/新闻去重/每日计划，服务器导入后启动四项能力。个人实例确认健康和相同迁移收据后才能切换。完整步骤位于Backend仓库 `deploy/BusinessDeployment.md`。

GUI端口扫描不会绕过已有日程的数据迁移。无远端能力时不改生产地址，也不偷偷启动本机替身。

## 可用状态

浅绿代表本机可用，青绿代表远程可用，灰色代表不可用。远端业务不仅检查节点注册，还要通过真实业务HTTP健康报文。模型、ASR、浏览器和视频工具依赖缺失时，对应后台功能灰灯，其他功能独立运行。

VPS附件上传上限30MiB、结果下载上限32MiB；大视频使用受支持的公开视频URL或直连接口。浏览器采集限制公开HTTP(S)、固定已校验IP、受限资源数和字节数，不共用个人浏览器登录态。
