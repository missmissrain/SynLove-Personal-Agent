# 日志与路径规范

## 日志

- 统一实现：`services/LogBus.py`
- 日志目录：生产根 `runtime/logs/`（可用 `SYNLOVE_LOG_DIR` 覆盖）
- 每个服务一份：`<service>.log`（10MB × 5 轮转）
- **总日志**：`all.log`，所有服务追加，一行一个事件
- 无控制台进程（pythonw）的标准输出：`<service>.console.log`
- 行格式：`时间 级别 [服务] 模块:行号 内容`

接入方式（入口两行）：

```python
from services.LogBus import bind, capture_stdio, install_excepthook
LOG = bind("facts", ROOT)
capture_stdio("facts", ROOT)
install_excepthook(LOG)
```

已接入：facts、message、iteration、plugins、asr、watchdog、guard、modelhub、business-*、
terminal-server/client（后三者下次重启生效）。

## 路径

- 仓库内路径一律相对库根；配置里不再出现盘符
- 统一解析：`services.ProjectPaths.resolve(root, value)`
  - 支持 `%VAR%` 环境变量、`{python}`、`{root}`、`{repos}`、`{prod}` 占位
  - 相对路径按库根解析
- 机器相关项（模型目录、adb、外部程序）只出现在 `ops/synlove-server.env` 或系统环境变量
- 已改：`iteration.json`、`screenInitiative.json`、`rehearsal.json`、`terminalConnection.json`、
  `windowsMcpConfig.json`、`voiceConfig.json`；`ProjectPaths`、`JobRegistry`、`UsageInference`、
  `AsrSession`、`runStreamingAsr`、`StreamingAsrServer`、`WindowsDesktopService`、
  `CodexDispatcher`、`SoftwareCommandResolver`
