# 夜间复盘与仓库维护

技能复盘与代码维护是两个独立任务，不占用主人格会话。技能复盘每日03:00执行，维护建议安排在03:30。已有依赖直接复用，不自动安装依赖或替换模型。

两项任务均使用Codex，默认先查天选笔记本的真实在线状态，离线时才使用服务器Codex。天选在线但版本不兼容或请求状态不明时停止并留下任务ID，不自动切到服务器重复执行。异步编码协议复用签名终端通道，源码包、结果与补丁走既有文件传输并校验哈希。GUI“功能设置”可配置开关、首选设备、离线兜底、执行时间、超时、每晚仓库数量与自动应用。

## 技能复盘

复盘读取真实对话及工具回执，并先脱敏。素材从最早未处理记录开始分批读取，同一时间戳的记录不会拆开。每轮默认最多6批、最多3个技能；预算耗尽保留后续水位，模型失败只推进已经成功完成的批次。材料不足保留待合并，不再因截断丢掉早期记录。

缺少可引用工具证据、使用降级模型的候选只进入待审目录。已有技能修改继续待审，相同内容不重复生成待审文件。格式和证据引用检查不等于完整语义审查；接口语义、适用范围仍需评审。结束时记录完成心跳，避免遗留“运行中”状态。

## 代码维护

复制 `config/nightlyMaintenance.example.json` 为私有配置 `config/nightlyMaintenance.json`，登记实际仓库路径与离线验收命令。配置与凭据不提交。

执行 `python tools/RunNightlyMaintenance.py --check` 可检查配置和Codex定位；直接执行则运行维护。默认每 3 天维护全部已登记仓库（`maxRepositoriesPerRun=0`），单仓库 900 秒，每仓库最多 20 个修改文件。独立计划任务运行；同一天不重复执行，有后台任务时推迟。失败结果不自动重放。

维护以当前文件为基线创建私有隔离副本，包括尚未提交的源码；不复制私人配置、密钥、运行数据、模型或依赖。Codex只接收已脱敏的有限对话和日志，使用独立上下文。仓库默认只生成待审补丁。只有 `autoApply=true`、改动全部落在 `autoApplyPrefixes` 登记的低风险路径内，且 `scopeChecks` 按改动范围追加的回归全部通过时，才自动应用；其余一律留在待审目录。`scopeChecks` 用路径前缀映射测试命令，例如改 `backend/packages/webhook/` 就跑 `tools/RunMemoryGate.py`。

宿主检查补丁路径、Python/JSON 语法、仓库级 `checks` 以及按改动前缀命中的 `scopeChecks`。禁止删除、凭据变动和启动脚本变动。验收失败保留隔离区；原文件发生并发变化则取消应用。应用前保存原文件，逐文件原子替换，失败时撤回本轮尚未被别人改动的文件。所有生产Git暂存状态保持原样。

产物位于 `runtime/nightlyMaintenance`：脱敏材料、状态、隔离源码、Codex输出、测试日志、补丁、原文件备份与QQ回执。没有配置发布流程时不会自动提交或推送GitHub。补丁应用与运行服务重新加载是两个步骤，部署策略需与具体服务对应。

## OpenCode统一入口

软件定位优先发现桌面版管理的 `opencode-cli.exe`，避免把GUI启动器当成CLI。1.x保留原参数；2.x使用用户共享服务，工作目录由宿主设置，不再传已取消的 `--dir` 和默认旧服务 `--attach`。显式配置的服务地址会转换为 `--server`；导出会话转换为 `session export`。保留旧会话数据库，不直接修改历史表。
