# 自迭代微服务（8820）

## 定位

系统里所有「自动执行、自动更新、自动维护」的逻辑只允许存在一处：`iteration/`。
其它进程不自己起定时器，也不自己判断该不该跑。

## 边界

| 归属 | 内容 |
|---|---|
| 自迭代微服务 | 预演、技能沉淀、代码维护、知识图谱更新、时间线更新、定时任务与重试 |
| 事实微服务（8802） | 在场、位置、监听目标、设备状态采集 |
| 消息微服务（8805/8812） | 微信 / QQ / 语音收发、投递回执、通道状态、ASR 开启 |
| 看门狗（guardService 等） | 只负责进程存活与链路自愈，不再承担任何调度 |

区分标准：**看门狗让系统活着，自迭代让系统变好。**

## 接口

- `GET /health`：存活
- `GET /v1/status`：每个任务的 `nextAt`、`running`、`exitCode`、`seconds`、`attempts`
- `GET /v1/jobs`：任务定义（命令、计划、超时、重试）
- `POST /v1/jobs/<name>/run`：立即执行一次，返回 202

## 已登记任务

| 任务 | 计划 | 内容 |
|---|---|---|
| `skills` | 每天 03:30 | 自动沉淀与评审技能 |
| `maintenance` | 每天 03:40 | 夜间维护与代码改进 |
| `rehearsal` | 每天 03:10 | 图谱有新内容时跑一轮预演 |
| `rehearsal-journal` | 每天 03:20 | 预演日记归档 |
| `memory-tick` | 每 15 分钟 | 时间线摘要 + 知识图谱增量更新 |
| `proactive` | 每 5 分钟 | 主动研究：同步画像、静默查资料、按作息决定是否播报 |

`memory-tick` 走消息服务的 `POST 127.0.0.1:3081/admin/memory-tick`，因为时间线与图谱的
内存缓存只在微信连接器进程里；连接器用 `DSH_MEMORY_SCHEDULER=external` 关掉自己的定时器，
只保留 `run_once` 供外部驱动。

`proactive` 同理：连接器以 `DSH_PROACTIVE_SCHEDULER=external` 关闭自带 tick，
由 `RunAdminTick.py --action proactive-tick` 每 5 分钟驱动一轮。
两处都只有「什么时候跑」被交出，研究、画像同步、播报时机判断仍在连接器内执行。

## 失败处理

- 子进程退出码非 0 → 记录 `exitCode` 与 `error`，按 `retries` / `retryMinutes` 顺延重试
- 重试次数用尽 → 按原计划等下一轮，状态文件里保留失败证据
- 单个任务异常不影响其它任务；调度线程本身不退出
- 每次执行追加到 `runtime/iteration/logs/<任务>.log`，状态写 `runtime/iteration/state.json`

## 与计划任务的关系

`SynLove-SelfIteration` 只有一个开机触发器，负责把服务拉起来；具体跑什么、什么时候跑由
服务内部的 `Scheduler` 决定，不再依赖 Windows 计划任务的时间表。
旧的 `SynLove-Rehearsal`、`SynLove-RehearsalJournal`、`SynLove-SkillReview`、
`SynLove-NightlyMaintenance` 已停用。

## 临时任务与周期任务

两类「任务」的归属不同，不能混在一处：

| 类型 | 例子 | 归属 | 原因 |
|---|---|---|---|
| 周期任务 | 预演、技能沉淀、夜间维护、记忆更新、主动研究、提醒轮询、日报领取 | **自迭代服务** | 什么时候跑是系统策略 |
| 临时任务 | 主人说「帮我把这份报告整理一下」「十分钟后提醒我」 | 消息层 `TaskRuntime` / 提醒服务 | 一次性、带截止时间，需要人格会话与工具 |

判断标准：**任务本身由谁定义、失败后要不要重排**。周期任务的节奏由 8820 决定；
临时任务由主人当场决定，执行完就结束，不进入 8820 的任务表。

`agentTasks` 表只有 `deadlineAt`（截止时间），没有 `cron` 或 `repeat` 字段，所以执行内核里
不存在周期任务，无需迁移；提醒的「到点触发」现在由 8820 的 `reminders` 任务每 30 秒驱动一次。
