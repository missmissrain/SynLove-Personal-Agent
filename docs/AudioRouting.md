# 统一音频投送

音频投送独立于采音设备。主动屏幕交互、手机语音回复及主人格短语音工具共用
`voiceRouting` 模块，不再分别决定播放去向。固定参考音、参考文本和音色参数不变，
主人格每轮仅提供情绪。

## 选择顺序

1. 主人明确要求文字：不播音。
2. 主人明确指定设备：只投该设备；离线就通过QQ询问，不自动改投别处。
3. 未指定时：优先唯一高置信的实际耳机媒体输出。两台电脑都有键鼠输入，不再一律禁用语音。
4. 摄像头确实识别主人在场时，作为高权重证据；仅有摄像头、有人脸或连接过耳机不算。
5. 扬声器自动播音还需既有外放授权，或主人明确允许接下来语音聊天。
6. 无法可靠选择：通过主人QQ询问目标，最多每30分钟询问一次；
   同一未回答问题六小时内不重复询问，主人更新设置后解除等待。

`mode=tts` 是明确允许语音，`mode=qq` 是文字，`mode=auto` 是自动判断。
明确指定目标默认保留一小时完整权重；一小时后进入一小时衰减窗，置信度从1连续降到0，
期间仍会参与设备选择但会逐渐让位给新的耳机、媒体输出、摄像头和活动证据，之后自动恢复
`auto`。可以用`durationSeconds`自定义完整权重时长，最长30天，不能设置永久锁定。
这只是音频路由授权，不绕过主动行为的安静时段、敏感内容、忙碌和频率限制。

## 主人格工具

- `terminal_audio_route`：status/set/clear。设置设备前通过terminal_devices匹配真实ID。
- `terminal_audio_reply`：短正文加本轮情绪，适用于QQ等文本通道转为语音的对话。
  现有语音回合由流水线合成，不能重复调用此工具。

示例：`{"action":"set","mode":"tts","target":"实际登记ID"}`（默认一小时）。
“先用文字”设置qq；“恢复自动选择”执行clear。
仅保存设置不能称为已经播放；只有played回执才表示目标执行器确认播完。

## 接口

主项目语音网关持有 `POST /v1/audio/route`，只在回环地址提供。
终端管理接口鉴权后代理同一路径，复用既有MCP连接，不增加公网端口。
action支持status、set、clear、resolve、speak和受信摄像头管线专用的camera。
摄像头动作不开放给主人格设置工具。

摄像头证据包含deviceId、observedAt、present、ownerConfidence、wearingHeadphones。
设备必须已登记摄像头能力；观察90秒有效，默认主人识别置信度至少0.90。
不得把设备在线、普通人脸检测或模型猜测当成主人识别结果。
本次提供接入和路由权重；尚未新增摄像头拍照及主人识别模型。

独立配置为config/audioRouting.json；范例为audioRouting.example.json。
偏好和摄像头证据在runtime/voiceRouting/state.json，不提交公开仓库。
短语音工具的结果在delivery.jsonl，仅保存目标、时间和结果，不保存正文和录音。

## 投送复核

音频上传后、播放前重新检查目标、授权版本及路由原因。
耳机拔出、授权改变、设备离线或音频过期时取消；不会把已生成语音换机补播。
有耳机或摄像头证据时不强制要求持续键鼠操作，音频截止时间仍由终端执行器校验。
服务器终端管理采用线程HTTP服务，避免代理路由时回查设备产生自锁。
