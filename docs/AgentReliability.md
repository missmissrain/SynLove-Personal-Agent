# 主子 Agent 的检索、时限与结果交接

## 联网查询

主人格可以直接使用 `web_search` 和 `web_fetch` 进行简短的只读查询。多步调研和操作任务由独立执行会话处理。两类会话均使用统一搜索服务，执行工厂不会另挂 RSS 工具覆盖搜索。

千问搜索默认正文预算为 4096 token，工具最多保留 16 个来源。官方新模型使用百炼原生流式接口；第三方兼容网关保留 Chat Completions 请求方式。原生流缺少正式结束状态时按失败处理，达到输出预算时明确返回截断标记。

搜索请求期限为 120 秒，工具期限为 130 秒。取消和请求超时分别返回 `WEB_ABORTED` 与 `WEB_SEARCH_TIMEOUT`。搜索凭据由凭据服务解析，不应要求用户补充其他模型的密钥。

## 后台任务时限

默认总时限为 1 小时，剩余约 5 分钟时，主人格核对当前进度并在原消息通道询问是否续时。用户确认之前不会自动延长；到期保留执行记录并请求停止。短任务按总时限的十二分之一提前提醒，避免刚提交就预警。

`task_submit.timeoutMs` 可指定 1 分钟至 2 小时的总预算；运行中的 `task_message.timeoutMs` 可调整同一任务的总预算，计时起点始终为任务开始时间。提醒与最终结果使用不同去重身份，发送失败复用持久正文重试；任务完成、取消或延期后丢弃陈旧提醒。自动提醒轮次只能读取本任务状态、进度和总结，不能自行批准延期。

例如，已运行 20 分钟的任务设为 `3600000`，剩余约 40 分钟。时限持久保存，调整不会重建会话或重放工具。只向执行者发送“再延长一小时”的文字不会改变宿主计时器。

到期会取消执行会话，但已经提交的远程任务或外部命令可能仍在运行，应核实实际状态，不能自动重复执行。

## 结果与证据

正式总结、任务状态、原通道投递和主人格润色继续独立管理。任务结束后保留回复进度；超时或缺少最终总结时，主人格可以区分已完成、失败和未验证事项。

宿主从正式工具事件收集调用数量、显式错误和受控文件元信息，存入 `runtime/agentTasks/evidence`。这些记录不包含模型内部推理或完整工具输出。文件存在不代表内容正确，更不代表已经传到目标设备。

## 软件定位与通知送达

执行者遇到 PATH 缺失或 ENOENT 时，应先通过 `terminal_devices` 确定实际执行设备，再使用
`terminal_software_find(target, name)`。查找工具由终端仓库维护，覆盖本机配置、PATH、
注册表、运行进程和有限安装目录搜索。候选路径须进一步确认用途与版本；没有搜索结果不等于未安装。
Codex、OpenCode 及其微信命令桥复用同一定位适配器，支持版本子目录，配置路径优先。

任务通知单独持久记录送达状态。`task_status`、`task_result` 中的 `notification.status`
区分 `not_queued`、`queued`、`pending`、`waiting_context`、`sent`、`failed_terminal` 和 `missing`。
任务执行成功或通知已入队，不代表消息已送达。`sent` 代表发送接口已确认成功，不代表用户已阅读。

异步通知尝试使用最近保存的同一用户回复凭据，不再仅因超过十分钟就放弃携带。
平台拒绝时先有界退避；连续失败则等待新的入站凭据，用户再次发送消息后自动补发。
通知不阻塞当前聊天，已发送分段不会重复发送，正式任务通知不参与普通临时通知的过期删除。
漏部署专用通知提示词时回退已有主人格协议，并记录诊断事件。

微信平台本身拒绝主动投递时，系统不能保证即时送达，也不会擅自把消息发送给另一平台的未知收件人。

## 验证入口

使用现有依赖运行：

```powershell
node tools/BuildTaskRuntime.mjs
node --test tests/AgentTaskTests.mjs tests/QwenSearchTests.mjs tests/TaskRecoveryTests.mjs tests/TaskDeadlineTests.mjs
node --test tests/SoftwareAndNoticeTests.mjs
```

这些测试使用假模型、临时数据库和临时文件，不连接生产消息通道。真实搜索和设备传输应另行验收。
