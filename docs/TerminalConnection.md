# 终端设备接入

SynLove-Terminal-Connection 独立提供设备登记、远程命令、本机播放器与 Codex/OpenCode 完成观测。被控电脑只需运行终端客户端，无需同时运行欣爱 GUI 或 Agent 内核。

## 部署与连接

1. 在服务器旁部署终端仓库，使用其安装器启动服务器管理器。
2. 将主程序 `config/terminalConnection.example.json` 复制为私有 `config/terminalConnection.json`，填写终端仓库位置、服务器本机管理令牌和设备快照位置。相对路径均相对于主程序根目录。
3. 通过正常入口重启主程序，加载终端 MCP。
4. 在 GUI“通道 → 设备管理”生成一次性接入文件，在目标电脑双击终端仓库的 `Install.cmd`。

主程序管理器默认访问服务器本机的 `127.0.0.1:17864`；终端本机接口默认 `127.0.0.1:17863`。二者不直接公开到公网。跨机器的业务消息通过已配置 VPS 的 HTTPS/WSS API 传递。

密钥在终端生成，仅公钥和签名报文回传。一次性接入文件含私人中转信息，有效期十分钟，请私下交付。安装器复用已有 Python 环境，不自动重装依赖。

## 设备与权限

主页显示当前在线设备数量；设备管理展示实际心跳、名称、能力、启用状态及两类编码通知开关。名称可改，设备 ID 不变。预登记的安卓、ADB 或嵌入式设备只有适配器实现并通过通信检查后才可能上线。

主人格可直接查询设备列表；远程命令及播放操作由后台执行内核调用。目标不明确时应先确认设备，不按最近上线时间猜测。

## 音乐

服务器保留酷狗搜索、曲目解析与队列。私有 `config/musicPlayback.json` 设为 `mode=remote`、`transport=terminal`，`target` 填写设备管理返回的设备 ID，另可配置默认音量。无需指定目标电脑 Python 或脚本路径。

播放端自行维护播放器和播放 ID。目标离线会明确失败，不回退至服务器扬声器；超时不会重新点播。音乐接口返回播放进程和音频时钟，不能替代人工听感检查。

## 编码完成通知

每台终端只读自己的编码会话，向服务器提交最终摘要。服务器按设备通知开关控制是否交接到现有 QQ 出站队列，不新增平台消费者。

服务器终端管理器必须配置 `notificationTarget` 和 `notificationInbox`。前者为已确认的 QQ 接收人标识，后者为主程序 `runtime/dsh/backendNotifications`。未配置接收人时，开启来源的通知保留在服务器，关闭来源的通知被消耗；稍后开启不会补发这些关闭期间已处理的旧事件。GUI 会提示通知目的地尚未配置，不将设备在线或开关保存等同于消息送达。

首次观测建立历史基线；后续新完成记录按业务 ID 去重，失败或取消与成功分别表达。欣爱自身受管子任务继续走原主人格回报通路，不再由外部完成观察者重复通知。

## 升级与异常

同一终端仅允许一个进程占有本机接口；服务器另检查设备启动租约。计划内重启应先确认旧客户端停止，再按终端仓库文档交接启动租约，不能以启动新进程覆盖旧实例。

已经开始执行但无法确认结果的命令不会自动重做。查询原请求 ID，确认实际状态后再决定下一步。
