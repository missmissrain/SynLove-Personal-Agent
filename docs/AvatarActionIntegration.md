# 欣爱23动作接入

控制台现在可以使用已验收的23个完整动作视频。动作资源放在
`console/public/Avatar/actions`，清单和标签放在
`console/public/Avatar/config/ActionManifest.json`。

## 选择动作

服务器提供两个接口：

```text
GET  /api/avatar/actions
POST /api/avatar/action
```

主模型可以明确选择注册表里的动作名：

```json
{
  "action": "伸手安慰",
  "reason": "对话内容需要安慰"
}
```

也可以把本轮用户话语、回复、情绪和意图交给规则选择器：

```json
{
  "text": "我今天有点难过",
  "emotion": "低落",
  "intent": "安慰"
}
```

如果主模型的动作名无效，服务器会按关键词选择；没有可靠命中时保持
`基础动作`。每次选择都会增加`requestId`，控制台只在编号变化时播放一次，
避免同一个动作反复重播。

## 主模型选择建议

主模型只需要返回一个动作名，不要返回视频路径。可选动作名必须来自
`ActionManifest.json`。动作选择应该依据当前回复的主要意图和情绪：

- 安慰、难过、委屈：伸手安慰、垂眼抓袖难过、抬手拭泪伤心
- 倾听、收到语音：侧耳倾听
- 思考、分析：托下巴思考
- 困惑、解释：摊开单手困惑、微笑摊手
- 惊讶：睁眼捂嘴惊讶
- 生气：叉腰皱眉生气
- 欢迎、打招呼：挥手打招呼
- 展示、邀请选择：双臂张开掌心朝上
- 开心、庆祝：闭眼拍手开心
- 害怕、担心：缩肩后退害怕

只有当对话情绪或意图发生明显变化时才切换动作；普通连续对话保持当前
动作或基础动作。动作视频自身包含前后渐隐，不要在上层再叠加第二套人物。

## 控制台行为

人物卡载入动作清单后轮询当前动作状态。收到新的`requestId`时播放对应
完整动作视频，动作结束后自动恢复底层Live2D待机。Live2D仍负责原有的呼吸、
眨眼和轻微发梢运动；动作卡负责大姿态、手臂、服装和每个动作自己的五官。

这套接入不重新分割PSD，也不把动作视频误称为新的Cubism moc3。
