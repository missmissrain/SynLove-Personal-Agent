# 欣爱人物展示与动作接入设计

更新日期：2026-11-03。

## 全屏与颜色修正

### 最新交互调整

当前采用独立的`AvatarColorGrade`显示调色模块，保持无光照，不覆盖原始贴图或源模型。颜色链路的GPU往返测试误差为0；源贴图浅色区域本身低饱和，旧版逐通道提亮又进一步压缩了色差。新方案在显示色域分别处理亮度与色度，通过统一缩放色度向量限制色域，避免把粉色与眼睛一起推白。

同一姿势的实际画布对比：旧版平均亮度224.14，首轮保色调色224.53；蝴蝶结区域HSV饱和度从5.81%提高至14.13%，眼睛区域从5.75%提高至11.04%。用户要求进一步增加对比与饱和度后，当前饱和度系数从1.65调至1.90，明度曲线指数从1.08调至1.20；蝴蝶结饱和度进一步提高至16.10%，眼睛区域12.36%，头发平均亮度229.27，整个人物平均亮度222.44。白发保持明亮，粉色和较深轮廓更清楚。最新颜色证据位于`Outputs/AvatarColorMotionV8`。数值用于比较显示效果，不代表用户已经认可最终美术效果。

`AvatarIdleActions`独立管理点头、侧头倾听、左右看看和轻抬手回应四种小动作，自动选择时避免连续重复，平滑进入并回到待机。首次等待5至9秒，其后间隔10至18秒；配合自然眨眼、呼吸和轻微发梢摆动。轻抬手为受限的小幅动作，不是大幅挥手。

十分钟确定性模拟覆盖全部四种动作，骨骼矩阵无非有限数值，连续重复次数为0。四种动作逐一检查通过，最大边长比1.227，最大顶点位移0.0314模型单位，各动作均回到待机；这些检查不等于完整碰撞验收。

移除眨眼、动一动、口型试播和暂停四个用户按钮，自动待机不受影响。人物底部使用现有爱心艺术字的透明派生图，并将标语移到最下方。原始品牌图片不覆盖。

桌面宽度大于850px时，人物卡片高度固定为主区域可视高度，主区域不整体滚动，只有右侧信息栏独立滚动。指针在人物上滚动时，将滚轮传给右侧信息栏；Ctrl加滚轮不截获。实测滚动前后人物和标语位置保持一致。窄屏继续纵向排列以保留可访问性。

当前证据位于模型工作区`Outputs/AvatarColorMotionV7`，包括颜色对比、四动作截图、19.5秒真实GUI录屏及检查报告；本轮修改前的代码备份为`备份/SynLoveAvatarv1.5`。浏览器功能检查、六档窗口尺寸检查和滚动固定检查通过，无WebGL或页面错误。未重启Electron桌面进程，桌面窗口加载新版需刷新或重新打开。

主页覆盖旧版`main > .panel`的1180px最大宽度，仅影响概览，其余页面维持原阅读宽度。宽屏按照实际窗口展开人物与信息栏，同时增加统计、连接和服务的字号、行高与间距。较矮宽屏单独收紧纵向间距；小窗口沿用紧凑双栏，窄屏改为纵向排列。

历史记录：V4曾使用1.7提亮，V5提高到3.2；两版仅以亮度与过曝检查验收，没有充分检查颜色保留，后续审查确认逐通道提亮导致饱和度下降。当前已替换为上述保色调色，历史曲线只保留为测试对照。封装PNG直接复制原字节；此处是显示风格校正，不是恢复丢失的贴图细节。

V4历史验证目录为`Outputs/AvatarResponsiveV4`，当时平均亮度从约185提高至206。当前重新覆盖1920×1080、2560×1440、1440×900、1280×720、960×720、760×720，使用实际GUI并启用桌面标题栏样式，检查面板宽度、横向溢出、字体与其他页面标题。截图只用于界面与显示验证，不表示消息通道连接或业务服务已经验收。

## 当前交付

控制台概览已接入真实 WebGL 三维人物，源模型为用户认可的嘴部 F 版，继承双眼精修 R 版。不是播放人物GIF，也没有调用外部图片服务。

已实现：

- 概览左侧人物陪伴区，右侧承载原有真实统计、消息连接、能力服务、定时任务和最近动态。
- 暖白与浅粉背景、圆角卡片、底部爱心艺术字与标语，人物区无动作按钮。
- 自然眨眼、胸肩呼吸、左右手臂错相待机、发梢阻尼摆动，以及四种自动小动作。
- 指针进入人物区时轻微转头跟随，离开后平滑恢复自主待机；不假装模型已有独立眼球。
- 保留内部眨眼和三秒口型预览测试接口，不显示用户按钮。停止整个人物上下平移的假呼吸。
- 开合继承认可模型的真实形态目标，运行层保留眼皮肤色、右睫毛及发丝遮罩。
- 口腔内壁保留顶点色渐变，避免导出后错误显示白色。
- 默认展示双臂放松姿态，仅作用于导出副本，不修改认可模型文件。
- 默认30fps，像素比上限1.5。隐藏页面、离开概览时停止实际画面渲染；内部暂停接口用于测试。
- 人物资源失败时显示已认可模型的静态图与错误说明，原控制台仍可导航。
- 本机静态资源提供渲染库、模型和纹理，页面不依赖外部CDN。

未实现：

- TTS音频与嘴型同步，音素级口型。
- 对话或后台任务状态驱动人物动作。
- 第三方动作文件导入、通用动画片段播放与外部动作重定向。
- 眼球转动、眉毛表情、笑脸等模型中不存在的形态目标。
- 独立桌面透明人物窗口。

内部口型预览仅播放本地动画，不代表已经启用语音对话。

## 现有模型的能力边界

原模型有身体、头颈、双手十指骨架，原有一段挥手预览动作。已认可面部控制为 `Blink.L`、`Blink.R` 与 `Mouth.Open`。

已有嘴眼控制可以直接用于互动。第三方表情不能直接复制到本模型：形态目标依赖具体网格拓扑与顶点对应关系。可以复用表情控制的命名与调度方式，但仍需为欣爱制作眉眼和笑脸形态。

已有身体骨架可以用于外部动作适配，但需要映射骨名、初始姿态、骨轴、比例及运动幅度。尤其不能跳过袖口、肩膀和手部穿模检查。

## GUI动线

概览保留单一主导航，不额外增加一套复杂的人物控制菜单。

- 左侧是欣爱，保持足够留白，不在人物身上叠放统计标签或工具输出。
- 右侧继续展示真实运行信息；定时任务和最近动态仍保留，允许纵向滚动。
- 人物区保持可见，右侧信息增加时不要求人物无限长高。
- 试播控件保持轻量，不显示伪造的在线状态、不生成虚构聊天气泡。
- 未来有正式对话入口后，人物气泡只显示短回复；长任务完整报告通过“查看结果”打开。
- 维护、成本和调用链仍放原有诊断页面，不让人物区成为另一个监控面板。

第二轮界面采用大幅半身构图，人物画布覆盖整个人物展示面，标题与轻量按钮叠放在留白处。去掉人物外围的重边框，减少顶部重复说明。右侧依次显示紧凑统计、消息连接、并列的定时任务与最近动态、能力服务。原始数据容器与事件绑定保持复用。

默认姿态按骨架空间的方向调整双上臂与前臂，使双臂放松向下、前臂略向前；不再给左右手套用同一局部轴角度。仅烘焙运行资源，保留源模型、面部拓扑与无光照材质。

## 事件与动作控制

动作控制器应在GUI本地运行，服务端仅传递事实与有限的表现建议。自然眨眼和呼吸不调用LLM，不新增token消耗。

建议下一阶段接收的事件：

| 事件 | 表现 | 约束 |
| --- | --- | --- |
| 对话输入开始 | 轻侧头，表示倾听 | 只针对本轮对话 |
| 主人格生成回复 | 短暂思考状态 | 不随后台长任务一直持续 |
| TTS开始/音频帧 | 嘴部跟随音频包络 | 以实际音频播放为准 |
| TTS结束/中断/失败 | 平滑闭嘴，恢复待机 | 不允许停在半张嘴 |
| 后台任务完成 | 一次小幅点头或挥手 | 多个完成事件合并提示 |
| 用户点击人物 | 短暂注意动作 | 限频，不触发无授权业务 |

优先级：用户显式控制 > 正在播放的语音 > 一次性回应 > 待机。眨眼作为独立层，身体动作按骨骼遮罩混合；同时动作不能争写同一骨骼。

长任务在子进程运行时，主人格仍可聊天，人物也继续待机。子任务不直接改GUI人物状态，不让“正在处理”永久占用人物表现。

LLM若将来提供表现建议，只允许有限枚举，例如 `neutral`、`nod`、`wave`，并校验持续时间和限频。禁止接收任意脚本、文件路径或不可信动作下载地址。

## 首批正式动作建议

1. 待机：轻微胸肩呼吸，独立自然眨眼。
2. 注意：轻侧头再回正；当前没有独立眼球，不做眼球跟随承诺。
3. 确认：一次小点头。
4. 欢迎：短幅度挥手，结束时自然回到待机。
5. 完成：轻点头或小幅挥手，与提示频率合并。

先保证少量动作的过渡和穿模，再扩展摇头、害羞、开心等表现。现有挥手预览也要整理起止姿态后才能作为正式动作。

## 当前渲染实现与后续迁移

实现目录：`console/public/Avatar`。

首版采用`SynLoveAvatarPreview1`，当前升级为`SynLoveAvatarRig2`：无姿态网格、三个嘴眼形态增量、原纹理、眼周遮罩、口腔颜色、52根骨骼、绑定逆矩阵与发梢遮罩。文件清单包含源模型哈希，不包含用户绝对路径。

嘴眼形态先作用到原网格，再使用与Blender一致的线性蒙皮，使闭眼与张嘴能跟随头部运动。所有原有效绑定都在四权重内，无截断损失；导出时将CPU蒙皮与Blender求值网格逐点比对。中性姿态最大坐标误差约0.000000212模型单位，源文件哈希不变。当前仍不能直接给该资源挂Mixamo或VRMA。

`AvatarMotionController`管理头颈、胸肩、手臂、指针跟随与一次性回应，`AvatarHairSpring`只管理发梢受限位移。每帧从固定初始姿态叠加动作，不累计修改基础旋转。暂停不推进动画时间，恢复时限制时间步长，减少突然跳动。

发梢遮罩排除整个独立面部网格岛与固定发根。左右发梢有不同相位，跟随转头产生轻微惯性，位移硬上限0.0018模型单位。这不是完整发丝碰撞或布料模拟，不对任意大幅动作的防穿模作承诺。

首次较大手臂回应在测试中出现边长拉伸，已经缩小；不直接播放来源不明的大幅挥手。遵循系统“减少动态”设置时停止自主骨骼和发梢运动，显式用户预览仍可操作。

外部骨骼动画接入时，保留人物卡片与调度接口，替换资源加载层为骨骼GLB/VRM，继续保留当前眨眼材质适配。不要为了加载整套骨骼系统而牺牲已经认可的脸部外观。

原始纹理保留8192分辨率，骨骼网格二进制约17.2MB。优先保住认可外观，尚未做纹理压缩或低配设备专项性能验收。
