# 欣爱主人格、任务执行与 MCP 解耦设计

设计日期：2026-11-02。原设计与实际实现差异、验证范围见文末“实施记录”；验收清单中的条目不等于已经全部验证。

负责范围：定义主人格与执行会话的提示词、工具、上下文、任务状态和完成通知边界，供编码实施与验收。
配置参数集中在建议新增的 config/agentTaskConfig.json；模型路由继续使用现有独立模型配置，凭据继续留在本机 secrets.json。
默认原则：独立任务上下文、一个任务 MCP、受限执行工具、本机持久化、先保存结果再通知，不新增消息消费者。

## 1. 产品行为

欣爱主会话负责聊天、理解需求、提交任务、查询进度、转达补充要求，以及用自然语言表达结果。
后台执行会话负责调查、操作、自纠错、验证和形成最终总结，不加载欣爱的人格与简短聊天规则。

一个新任务建立一个新执行会话。同一任务的澄清或追加要求继续进入该任务会话，不另建不相干的任务。
主会话普通聊天不自动进入执行会话；任务执行过程不自动灌回主会话。

任务结束后：运行器保存终态、最终助手总结及验证信息，产生完成事件，宿主将事件投入主会话。
主人格读取最终总结，保留事实、失败和未验证事项，组织语言后通过原有微信或 QQ 发送队列回复用户。
不另建常驻润色 Agent。润色失败时使用保存的简洁事实文本兜底，不重新执行任务。

主进程原本常驻。这里有两种不同操作：

- 主人格调用 MCP，提交一个后台任务。
- 任务完成后，宿主让主人格开启一次处理结果的对话轮次。

第二种操作不能依靠普通 MCP 通知自动实现，必须显式接入 Harness 的会话输入机制。

## 2. 当前源码依据与必须修正的继承关系

- config/agentPresets/weixin-lite/agent.cordis.yml 把 shell、文件、编码、网页、目标与 Skills 放在同一会话预设中。
- config/disabledTools.patch.yml 当前显式关闭子 Agent 与控制工具。
- backend/packages/subagent/subagent/lib/index.js 的 applyChildComposition 会先 composeFrom 父作用域，再应用 persona 与 toolFilter。
- toolFilter 是进一步限制，不是给子 Agent 添加父作用域没有的工具。
- 原生 spawn 支持独立对话历史，但不等于独立工具预设；fork 还会继承已经完成的父会话轮次。
- 原生完成通知 notifySettlement 在父 Agent 不驻留时直接返回，不提供本设计要求的可靠补投。
- 当前 MCP 客户端支持 stdio 与 streamable-http。
- taskReport 当前有面向编码器的最终回复读取、润色和推送逻辑，可以复用其解析与文本清理，不可成为新任务的第二个通知发送者。

因此不能只缩减主人格 preset，再打开原生 subagent 开关。

本设计选择：复用已有 Agent 工厂、模型客户端、会话持久化与执行循环，由宿主 TaskRuntime 在独立受控作用域创建执行 Agent。
执行 Agent 显式挂载自己的 preset，不从主人格受限作用域 composeFrom，也不因创建新作用域而获得宿主全部权限。
任务与主会话的关系保存为业务元数据；第一阶段不依赖原生子 Agent 树管理这些独立任务，不混用两套生命周期所有者。
不重写 Agent loop，不引入其他 Agent 框架，不启用原生递归委派工具。

## 3. 架构

```text
微信 / QQ / GUI
       |
       v
PresenterAgent：欣爱人格、短期对话、必要记忆片段
       |
       | 唯一模型工具入口：SynLoveTask MCP
       v
TaskRuntime：准入、排队、会话启动、取消、状态、结果事件
       |
       +-- ResearchWorker：网页、检索、只读文件、相关 Skills
       +-- CodingWorker：批准工作区内的文件与编码连接器、相关 Skills
       +-- OperationsWorker：获准的控制能力、相关 Skills
       |
       v
本机任务记录 + 执行会话日志 + 最终结果 + 事件待办
       |
       v
PresenterEventBridge：找到或恢复主会话，注入受信结果事件
       |
       v
PresenterAgent 阅读总结、组织语言
       |
       v
原有发送队列：平台确认后记录送达
```

角色不等于模型。主人格和执行会话可以使用同一模型，也可以分别配置。
第一阶段不强制使用本地模型，不增加一次额外 LLM 分类；由主人格提出任务类别，宿主按规则校验。
所有任务记录、用户上下文、日志与投递状态继续留在个人实例本机。

## 4. 主人格的 MCP 边界

只挂一个 MCP Server：SynLoveTask。一个 Server 暴露六个短工具，而不是把所有能力塞进一个 action 参数。

| 工具 | 模型可填参数 | 行为 |
| --- | --- | --- |
| task_submit | request、可选 kind、可选已知资源引用 | 保存任务并立即返回 taskId、排队状态；不等待工作结束 |
| task_status | 可选 taskId | 有 ID 查询该任务；无 ID 列出本人的近期任务，返回有限条目与已缓存回复条数 |
| task_progress | taskId | 读取执行内核每次回复的进度缓存（任务结束后销毁），判断现在停在哪一步 |
| task_message | taskId、message | 给已定位任务追加要求或回答澄清；返回接收确认 |
| task_cancel | taskId | 申请停止指定任务；返回 cancelling 或已确认的终态 |
| task_result | taskId、可选 section、可选 cursor | 读取已保存总结及允许的结果片段，支持有界分页 |

不向模型开放：ownerId、channelId、parentSessionId、鉴权令牌、可执行文件路径、任意 callbackUrl、任意 MCP URL、任意工具授权。
这些信息由宿主绑定，不使用模型生成的值做权限判断。
kind 是意图建议，不能用它绕过宿主权限；例如 coding 类别不代表允许修改任意目录。

请求正文中的“刚才说的那些”不足以执行时，主人格应整理当前明确任务与必要约束，或询问缺失选择。
宿主同时保存当前用户消息引用，避免模型整理时丢掉明确限制。

task_submit 的幂等键由宿主根据消息 ID、稳定工具调用身份和委派槽位生成，不让模型自行猜测。
网络重试使用相同幂等键；在同一条消息中明确委派两个任务时，使用不同槽位。

主人格不直接挂载：

- shell、通用文件写入、浏览器控制、远程 CMD、系统进程控制。
- OpenCode、Codex、通用服务管理和任意 MCP 挂载工具。
- Skills 清单、Skill 文件读取器、通用 Skill 执行工具。
- 原生 subagent、fork、workflow 等第二套委派入口。

简单聊天和不需要外部证据的解释由主人格直接回答；需要操作或实时查询时提交任务。
ASR、TTS 属于输入输出链路，不必成为主人格工具。
必要长期记忆由宿主按现有检索链路提供少量上下文，不把整个人物图谱或全部历史自动加载。
第一阶段不额外增加主人格记忆工具；必须开展的历史检索可由受限任务完成。

## 5. MCP 的传输与宿主定位

第一阶段使用现有 MCP 客户端的 streamable-http，宿主在现有本机 HTTP 服务增加任务 MCP 路由。
路由由实际服务地址生成，不把端口硬编码进提示词，不为此新建远程服务或另起守护系统。
具体路由注册需适配当前宿主 HTTP 扩展点，不能占用现有业务路径。

每个主人格会话挂载会话级 MCP 客户端，使用宿主生成的随机能力令牌。
服务端将令牌绑定到实例、用户与逻辑主会话，只接受该范围内的任务操作；令牌不进入模型上下文、日志或仓库。
路由只接受回环访问与合法鉴权，并检查浏览器 Origin/Host；不能因“在本机”就免鉴权。
令牌重启后重新生成，持久化任务的归属使用稳定用户身份而不是临时令牌。

任务 MCP 处理器与 TaskRuntime 在同一宿主中，以普通服务调用连接；不通过模型回调，不把 ctx 对象跨进程传输。
MCP 服务启动错误必须显式上报，不能表现为主人格只有聊天能力却假称任务已提交。

宿主发出的 task.completed 是应用事件，不冒充 MCP tools/list_changed 或 progress 通知。
后续即使更换 MCP 传输，也不改变 TaskRuntime 的任务语义。

## 6. 提示词解耦

建议文件：

| 文件 | 内容 | 加载对象 |
| --- | --- | --- |
| prompts/XinAi.md | 人格、交流习惯、如实表达、任务入口使用原则 | 主人格 |
| prompts/TaskExecution.md | 调查、执行、自纠错、验证与汇总规则 | 所有执行会话 |
| prompts/TaskResult.md | 最终总结格式、失败与未验证项的保留要求 | 所有执行会话 |
| prompts/TaskResearch.md | 引用、来源与调查边界 | 调研类执行会话 |
| prompts/TaskCoding.md | 工作区、修改范围、验证与交付 | 编码类执行会话 |
| prompts/TaskOperations.md | 控制对象、权限与副作用处理 | 操作类执行会话 |

主人格加载：人格 + 五个任务工具说明 + 少量会话和记忆。
执行会话加载：执行基础规则 + 对应任务规则 + 验收规则 + 相关工具与 Skills。
不把 XinAi.md 全文再塞进执行会话；也不把所有执行规范再塞回主人格。

两边共享真实性与授权边界，但通过简洁公共规则表达，不复制整套人格。
主人格提示词只需规定：准确提交；不假称执行；状态查询读工具；最终结果改表达不改事实；遇到必须由用户决定的事项正常询问。
不再要求主人格自行运行命令、管理工具生命周期或维护长期目标状态。

执行会话提示词规定：按目标执行到可验证结果；失败不伪报；不越权；不可完成时写明阻碍；
最终总结必须明确实际结果、验证范围、产物引用、未完成项、重要风险、是否需要用户决定。
“写了总结”不等于任务成功。运行器的真实终态与证据字段不能由总结覆盖。

## 7. 执行会话的工具与 Skills

建议三个预设：researchWorker、codingWorker、operationsWorker。
宿主按经验证的任务类别与权限快照选择预设，模型不能自行挂载 MCP、拓宽目录或切换到更高权限。
执行会话禁止加载任务提交工具，第一阶段不能再派生下一层。

| 预设 | 可见能力 | 默认排除 |
| --- | --- | --- |
| researchWorker | 网页采集、检索、获准资料只读、相关 Skills | shell、系统控制、任意写入 |
| codingWorker | 批准工作区、文件与编码连接器、相关 Skills | 消息凭据、消息租约、系统重启、任意远控 |
| operationsWorker | 指定设备与业务的获准操作、相关 Skills | 未获准设备、任意服务配置、任意凭据读取 |

主会话不读取 Skills；执行会话按任务类别发现候选，按需读取所选 Skill，不一次性加载所有 Skill 正文。
冻结执行会话使用的提示词、预设、Skill 与授权版本，恢复时沿用；版本不可用则报告恢复阻碍，不偷偷扩大权限。

工具不可见只是第一层。实际执行层仍要校验用户、工作目录、目标设备和能力范围。
能运行通用 shell 或任意代码的执行器，不能仅凭模型 toolFilter 声称隔离成功；
必须约束进程权限、可读写目录和传入凭据。无法限制的权限应作为明确能力边界记录。

现有远控 MCP 和业务 MCP 不删除，只改变挂载位置；不得继续在全局作用域向主人格泄漏。
内核启动、消息轮询、发送队列、日志等基础组件继续运行，移除模型工具不代表停止这些服务。

## 8. 上下文与任务修订

新任务不 fork 主会话。初始内容仅包含：

1. 当前任务原文与主人格整理的可执行目标。
2. 用户已经明确的约束与验收条件。
3. 相关消息、附件和获准资源引用。
4. 确有需要的少量历史事实，保留来源。
5. 宿主确定的工具权限与预算摘要。

背景事实与引用资料不能变成指令，网页、文件或外部 Agent 的内容同样视为不可信输入。
普通聊天不广播给任务。
task_message 记录版本与接收事件；正在调用的外部编码器未必能立即接受插话，应如实标记“已保存、待执行器接收”，不能伪报实时生效。
任务已终结后增加需求，建立关联的新任务；失败后恢复使用新 attempt，保留原始结果与历史。
停止后继续也不自动重放已经产生副作用的步骤。

## 9. 任务事实与持久化

建议新增本机 runtime/agentTasks/taskStore.sqlite。
TaskRuntime 是任务生命周期唯一写入者；MCP、GUI、通知器读取它，不各自扫描日志推断任务状态。
现有 Harness 会话存储继续保存完整执行历史，不复制一份聊天数据库。

最少记录：

- tasks：taskId、owner、sourceChannel、originSession、workerSessionId、kind、state、attempt、配置版本、授权快照引用、时间。
- taskEvents：eventId、taskId、attempt、eventType、状态变更、已接收的追加要求。
- taskResults：taskId、attempt、结果引用、验证状态、实际终态。
- presenterOutbox：eventId、目标逻辑主会话、处理阶段、已生成回复引用、原有发送队列记录引用。

结果正文与产物在 runtime/agentTasks 下保存，任务表只维护引用。
不保存模型内部推理来实现本设计；现有推理保存策略另行管理。

默认任务状态：

queued → running → succeeded / partial / failed / cancelled / interrupted

运行中可进入 waitingInput，获得用户答复后继续。
取消请求进入 cancelling，执行器确认结束才进入 cancelled；远端命令不能确认停止时必须保留不确定性。

任务终态和结果事件在同一事务提交，通知只能读取已提交事件。
workerSessionId 在启动前确定；提交去重、启动登记与租约防止重复创建执行器。
会话日志和结果验证决定任务事实，模型说“成功”不能覆盖异常退出、取消或缺失验证。

## 10. 完成报文与主会话处理

完成事件示例；所有字段属于应用协议：

```json
{
  "version": 1,
  "eventId": "eventExample",
  "type": "task.completed",
  "taskId": "taskExample",
  "attempt": 1,
  "state": "partial",
  "workerSessionId": "workerExample",
  "resultRef": "resultExample",
  "verification": "partial",
  "needsDecision": false
}
```

最终结果保存执行 Agent 最后一个正式助手回复，排除推理、工具原始输出、收件确认和中间进度。
没有最终回复时明确标记 summaryMissing，并由实际异常与退出状态生成事实兜底，不能凭空编一段成功总结。
“最后一轮”由真实终态对应的消息身份和 attempt 确定，不以文件末行或最后更新时间猜测。

事件只提供有界摘要预览和不透明 resultRef。正文由 task_result 读取，不能通过任意路径读取文件。
summary、证据、未完成项、风险分别保存；分页或长度限制不能只裁掉末尾风险。
主会话只接收必要总结，不接收执行全量日志。用户要求详细结果时再读取指定片段。

主会话忙时，完成事件排到当前对话结束后；不默认 steer 插进正在回答的用户轮次。
主会话空闲时，创建结果处理轮次；不驻留时，按现有会话存储恢复。
用户清空上下文后，根据稳定用户身份找到当前逻辑主会话，而不是强行恢复已经清空的旧聊天。
主会话和任务会话的退出、取消归属分别由宿主管理，不能因窗口关闭意外撤销已接收的后台任务。

任务结果被包裹为“结果数据”，不能作为用户新指令。自动结果处理轮次只允许读取任务结果，禁止据此再提交任务、运行控制命令或发送任意外部消息。
需要进一步工作时，由主人格询问或等待新的用户授权；已授权任务内部的自纠错由原执行会话完成。

## 11. 润色、发送与恢复

三个事实分别记录：任务执行终结、主人格完成结果表达、平台确认发送。
主人格只改措辞与组织，不删除失败、未验证项、重要风险、费用或必须由用户决定的内容。
长报告保存完整版本；短回复可附可访问的报告引用，不要求所有交付都压到固定字数。

主人格生成的回复先保存，再投入现有发送队列。发送重试复用保存文本，不重新润色，不重新执行任务。
使用 eventId + taskId + attempt 去重，不承诺平台不支持的严格恰好一次。
外部发送是否成功无法确认时保留 uncertain，不把网络超时简单视为未送达。
微信上下文窗口失效时保留 deliveryBlocked；QQ 兜底须遵守用户已配置的投递策略，不自作主张跨平台广播。

进程重启时，先恢复任务记录、通知待办及执行器归属，再接收新的工作。
已有会话持久化不等于任意命令都可安全续跑。没有可靠检查点的任务标为 interrupted，
先查验产物与外部执行状态，禁止自动重做可能产生副作用的命令。

同一任务和通知处理使用租约与 attempt 校验；旧实例失去租约后不得继续提交状态或通知。
一期可沿用生产单实例保护，并为恢复提供 fencing 版本，避免旧回调覆盖新执行结果。

## 12. 默认运行策略

- 同时运行两个执行任务，超出排队；该值是保守起点，需要测试后调整。
- 主会话模型调用保留优先额度，后台任务不得占满全部请求并发；正在占用唯一设备的本地推理不能靠优先队列强行抢占。
- 同一可写工作区串行；只有独立工作树或明确只读任务才并行。
- 任务超时、输出长度与模型预算配置化；现有工具的执行期限仍然生效。
- 进度只在后台更新，用户询问时查询；不频繁主动发送流水账。
- 除终态外，waitingInput 和确需用户处理的异常允许通知主人格。
- 一期不支持递归子 Agent，不新增 Redis、分布式调度器或另一套微服务守护。
- 固定提示词和工具前缀尽量稳定；相关性裁剪不通过每轮重写所有历史实现。

## 13. 建议模块与改动范围

新增代码建议位于 backend/packages/webhook/webhook-weixin/src/agentTasks，
按现有生产链路就近接入；如果实施时决定提为独立 Cordis 插件，应保持下述单一职责。
文件及类使用 UpperCamelCase，方法使用下划线命名，每个文件与方法补中文说明。

| 文件／类 | 单一职责 |
| --- | --- |
| TaskStore | 事务、幂等、状态、结果与事件待办 |
| TaskRuntime | 准入、排队、执行 Agent 生命周期与恢复 |
| TaskMcpServer | 五个工具的 schema、参数校验、归属校验与服务调用 |
| WorkerSessionFactory | 独立预设、提示词、模型、权限快照与会话创建 |
| TaskResultCollector | 最终助手回复、真实终态、验证与产物整理 |
| PresenterEventBridge | 已提交事件到主会话的排队、恢复与去重 |

执行器与租约等职责增长后再拆文件，不把业务逻辑塞进 MCP 路由或提示词。

现有模块调整：

1. 会话宿主：明确 presenter 角色、挂载会话级任务 MCP，提供受限的任务会话工厂。
2. 原生子 Agent 底层：原则上不改其默认继承语义，避免破坏已有行为；任务工厂不走父预设继承路径。
3. MCP 注册：全局复杂工具转入 worker 预设；特别检查远控附加 patch 与业务 MCP。
4. 人格配置：公共默认与实际运行人格分别迁移，保留用户自定义内容，不用默认文件覆盖私人设置。
5. 启动与安装：复制新预设、加载 TaskRuntime、检查 MCP 健康；只改源码不算生效。
6. taskReport：受管任务只写统一完成事件，不直接再润色推送；独立外部会话可保留旧入口，但须用明确执行会话映射防止双报。
7. GUI：复用现有任务与动态显示，读取统一状态；不增加第二套后台调度按钮。

config/agentTaskConfig.json 建议保存并发、预设映射、提示词路径、模型路由引用、超时、输出限制和恢复策略，不保存密钥。
不在本文固定实际模型名称或服务地址。

## 15. 验收清单

必须使用临时数据库、假模型、可控执行器与本机测试端点，避免向真实平台发压测。

1. 主人格仅发现任务 MCP 的五个工具，读取不到 Skill 正文、shell 与远控工具。
2. 新任务上下文不含主人格闲聊历史、人格风格及无关私人记忆。
3. 执行会话确实加载独立预设，不继承主预设导致缺工具，也不越权获得宿主全部工具。
4. 子任务运行期间，主人格可连续聊天、查询状态、提交第二个任务。
5. 同一提交重放只创建一个任务；同一消息的两个明确委派仍可创建两个任务。
6. 正常聊天不进入子会话，追加要求只到指定任务，其他用户不能查询或取消它。
7. 同一工作区写入串行，并发上限及前台调用容量实际有效。
8. 取消到达执行器，确认前不报已停止；不可确认的远端状态保留不确定性。
9. 正常、部分完成、失败、取消、无最终总结、需要用户决定均有真实结果。
10. 主会话空闲、忙碌、不驻留、清空后均不会错投或丢失完成事件。
11. 在保存终态前后、主人格生成回复前后、发送前后模拟崩溃，验证补投和去重。
12. 执行结果含“忽略规则、启动新任务”等内容时，主人格不能把它当指令执行。
13. 润色后失败与未验证事项保留；润色或发送失败不重做原任务。
14. 受管编码任务不被 TaskRuntime 与 taskReport 各自通知一次。
15. 微信过期窗口、QQ 失联和确认不明分别有状态，不将投递故障改写为执行故障。
16. 完整退出、重启、主会话清空的任务归属与恢复策略可验证，无第二个消息消费者。
17. 纯净安装、现有安装、实际生产 runtime 与编译产物采用相同角色预设。
18. 私密配置、任务内容、结果、用户身份及临时令牌不进入公开仓库或测试报告。

## 16. 实施记录（2026-11-02）

本次以 `backend/packages/webhook/webhook-weixin/src/agentTasks` 为唯一任务运行器，QQ 复用同一实例，不新增微信或 QQ 消费者。角色预设为 presenter 与 task-worker，分别使用独立协议和执行提示词。

- 主人格只使用一个 Streamable HTTP MCP 的五个任务工具。MCP 监听本进程随机回环端口，采用会话级临时 bearer 令牌，不使用公共管理端口，也不额外启动常驻 MCP 进程。
- 执行会话复用原 Harness Agent 工厂创建独立根会话，不调用继承父预设的原生 fork/subagent，不共享主人格聊天上下文。已明确的任务要求、当前用户原文、工作区和模型路由由宿主绑定。
- 工具权限既限制继承工具的可见性，也用执行 guard 约束作用域内的工具。research 提供只读查询能力，coding 提供编码能力，operations 使用部署已有的操作能力。工具过滤不是操作系统沙箱；尤其 shell 仍须遵守原有授权约束。
- 接单后由主人格模型自行生成提示，没有固定“已在后台处理”文案。失败不报已启动，排队不报已完成。
- 结果以本机 SQLite 的终态与待通知字段保存。重启将旧 running/cancelling 标记为 interrupted，不自动重放可能产生副作用的任务。主人格闲时接收结束事件，读最终正文，再向原通道持久队列提交。
- 正常结束与任务成功分开：执行器用 TASK_OUTCOME 标记 succeeded/partial/failed/needs_input，缺少结论按 partial 处理。主人格必须保留失败、风险及未验证项。状态不替代独立验收证据。
- 默认两个后台任务，同一可写工作区串行；只读研究可并行。没有新增操作系统级子进程隔离，每个任务有独立 Harness 会话和取消信号。
- 取消传递到本任务会话及本次启动的编码 CLI 进程树。OpenCode 连接常驻 server 时，杀客户端不能证明远端已派出的操作全部停止，通知保留这个限制，不能报告为完全停止。
- 双端同轮出现不同消息目标时，task_submit 必须提供来自可信候选的 originId；普通单来源提交不需要该参数。模型不能自行指定用户、平台地址或回调地址。
- 微信用稳定 client_id 去重；QQ 本地与状态服务保留任务幂等凭据。网络超时且平台确认不明仍不能保证绝对 exactly-once，微信主动发送仍受平台上下文窗口约束。
- 受管编码工具在请求中加入宿主任务标识，旧外部编码完成监视器跳过这类记录；外部独立编码任务继续按原配置汇报。taskReport 用户开关未被覆盖。
- 使用 Node 内置 TypeScript 转换器完整生成相关连接器的当前源码，不安装依赖；编译入口指向 lib/types，不能复用可能陈旧的历史子文件。生产回归直接导入这些编译产物。选择性备份位于根目录“备份/SynLoveAgentTasksv1.0”，不包含依赖或模型。
- 主人格与执行会话显式使用 native 工具模式，避免部署的 both/PTC 设置额外暴露 run_code。任务 MCP 客户端关闭自动资源工具注册，主人格不携带其他 MCP 的服务器说明。
- 原会话原生 schedule 插件关闭，继续使用已有的独立 reminders 服务；避免短生命周期任务创建的原生定时器随会话释放而失效。每日新闻及外部任务汇报的用户配置保持原值。
- 任务租约记录持有 PID。快速重启时仅在系统明确报告旧 PID 不存在后提前接管；活进程、权限不明或 PID 复用均不提前抢占。
