欣爱是一个跑在自己机器上的私人智能体：她有自己的声音、自己的判断、自己的记忆，
通过微信、QQ 和语音与你相处，也能调度你家里的电脑、手机与模型服务。

v3.0 是一次彻底的结构重构：代码、配置、数据、资产、技能全部按职责分层，
服务之间只通过 HTTP 与明确的接口交互，不再有「改一个文件、四处行为变化」的耦合。

---

## v3.0 重构结果

| 维度 | v2 | v3.x |
|---|---|---|
| 代码组织 | 4 个大库平铺，跨库 `sys.path` 随处可见 | 5 个库各自独立，跨库注入收敛到 7 处入口 |
| 项目绝对路径 | 163 个文件、352 处 | 代码与脚本 0 处（计划任务参数除外） |
| 设备管理 | 混在终端库 | 归入后台 `fleetService` |
| 共享代码 | 多份复制 | 各自内联，不再维护 SDK |
| 配置 | 散落各库 `config/` | 真实文件集中在 `models/config/`，统一解析 |
| 数据与技能 | 混在 `runtime/` | `data/`、`skills/` 独立目录 |
| 中转节点 | 3 份实现 | 1 份实现 + 2 份配置 |
| 发布 | 手工同步 | 脱敏快照，单次提交 |

## 微服务边界（v3.1）

| 服务 | 端口 | 职责 | 不做什么 |
|---|---|---|---|
| 消息网关 | 8805 | 微信 / QQ / test 通道收发、会话与来源登记 | 不碰设备、不写事实 |
| 语音 | 8812 | 唤醒、流式 ASR、TTS、播放路由 | 属于消息微服务，不独立占库 |
| 事实层 | 8802 | 在场、监听、设备状态、服务探活 | 不承载通道状态 |
| 自迭代 | 8820 | 预演、技能沉淀、维护、图谱与时间线、定时任务 | 不在请求链路上做长任务 |
| 插件 | 8830 | 音乐、桌面、爬虫等工具能力 | 不持有主循环，不反向调用人格 |

主人格只负责接待、回答、唤起任务和基础聊天；执行交给子人格。工具能力由 MCP 工具自身的描述和参数约束，不在提示词里写死链路。

## 通用媒体队列

列表播放（歌单、视频列表、图片列表）由服务器维护轮询队列，终端本地自动续播：

1. 主人格 / 子人格只调用一次工具，把前 N 项交给服务器。
2. 服务器逐项解析、经 `file.stream` 直传到终端，终端本地队列播放。
3. 当前项接近结束时服务器预取下一项入队；终端播完自动接上。
4. 支持 `kind = audio / video / image`；图片统一由服务器转成 5 秒视频再播放。
5. 队列状态、播放位置、`playbackId` 都可查询，暂停 / 继续 / 停止 / 下一首按真实回执返回。

## 功能全景

### 一、三通道相处

| 通道 | 能力 |
|---|---|
| 微信 | iLink 协议收发、会话窗口管理、主动消息、失败可见（不静默降级） |
| QQ | 官方机器人 / 主动消息收件箱、完成汇报、提醒推送 |
| 语音 | 唤醒词、流式识别、固定声线合成、播放路由与真实回执 |

### 二、语音

- 唤醒词检测（KWS）与流式 ASR，终端本地完成采音与降噪
- 固定声线 TTS（Breeze-TTS-2，int8 混合加载，6GB 显卡可跑）
- 长文本按句分段合成，避免爆显存与语气漂移
- 播放前复核：目标设备、授权版本变化就丢弃这条过时语音
- 耳机 / 扬声器 / 采集设备分离，不擅自改投

### 三、在场与主动

- 设备状态采集：在线、空闲、锁屏、前台窗口、地点、日程
- 模型判定 + 规则兜底，输出唯一的在场结论与监听目标
- 屏幕观察：截图理解当前在做什么，判断是否适合搭话
- 主动语音/文字：先复核来源与去向，过期不补播

### 四、设备集群

- PC 终端与安卓终端统一注册、心跳、能力声明
- 指令队列、幂等 ID、真实回执，不重放写操作
- 文件流式传输、断点续传、传输日志脱敏
- 语音信箱：设备不在线时暂存，上线后投递
- 远程控制：MCP 工具化，按设备能力授权，不越权

### 五、记忆

- 时间线：按天记录对话与事件，可检索、可摘要
- 知识图谱：人物、关系、偏好、事件的结构化沉淀
- 人物画像：从长期互动中提炼，不写死
- 会话持久化：重启不丢上下文，按用户隔离

### 六、技能与自迭代

- 预演技能（`skills/rehearsal`）与沉淀技能（`skills/production`）分离
- 夜间维护：检查、修复、整理，不打断主链路
- 技能评审：把预演中验证过的流程沉淀为正式技能
- 自迭代：在 `forks/xinai` 中修改，评审后合回生产，不直接动线上

### 七、模型

- 多 provider 路由与故障转移（云端 / 本地）
- ModelHub 统一登记模型、显存预算、加载/卸载协调
- 本地 LLM、Whisper ASR、Breeze TTS 常驻，按需加载
- 凭据只从 `secrets.json` 或环境变量读取，不进日志、不进仓库

### 八、内容与生活

- 音乐：酷狗搜索、点歌、播放控制；歌单由服务器轮询、终端自动续播
- 媒体：音频 / 视频 / 图片统一排队播放，图片默认展示 5 秒
- 日报与新闻：定时采集、模型筛选、推送
- 视频摘要、有声书脚本、长篇内容整理
- 提醒与待办：一次性和周期性，失败可见

### 九、运维

- 服务看门狗：事实层统一探活 18 个服务，离线按冷却自动拉起托管任务
- 计划任务与看门狗：单服务失败自动恢复
- 事实微服务：在场、监听、设备状态采集的唯一出口（通道状态属于消息网关）
- 自迭代微服务：预演、技能沉淀、代码维护、图谱与时间线更新、定时任务的唯一执行者
- 插件微服务：音乐、桌面、爬虫等工具能力统一 API
- 诊断与错误文件：失败写盘，能查、能复现
- 备份归档：按版本保留，删除前先打包留清单

## 快速开始

```bash
# 1. 安装依赖（Python 3.12）
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# 2. 准备配置（真实文件在部署根的 models/config/）
#    modelConfig.json / serviceConfig.json / secrets.json

# 3. 启动
.venv\Scripts\python.exe start_stack.py
```

启动后：

- `http://127.0.0.1:3080` Harness（会话与工具）
- `http://127.0.0.1:8802/health` 事实服务
- `http://127.0.0.1:8805/health` 消息网关
- `http://127.0.0.1:8812/health` 语音网关（与消息网关同进程）
- `http://127.0.0.1:8820/health` 自迭代服务
- `http://127.0.0.1:8802/v1/facts/services` 全服务在线快照
- `http://127.0.0.1:8830/v1/plugins` 插件目录（音乐 / 桌面 / 爬虫）

## 设计原则

1. **唯一事实源**：在场、监听、设备清单各有一个出口，其他服务只读接口。
2. **不降级**：依赖不可用就报错并写盘，不静默换路径、换模型、换设备。
3. **相对路径**：库内不写死盘符，入口脚本按自身位置解析根目录。
4. **库即边界**：跨库只走 HTTP / MCP / 明确的公共模块。
5. **脱敏**：密钥、令牌、私钥不进仓库，日志不写正文。
