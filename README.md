# SynLove-Personal-Agent v2.0

**心合万象 爱有回响**

SynLove 支持微信、QQ 对话与桌面控制台，提供独立的接待人格、后台任务、长期记忆和可配置服务连接。主程序在个人电脑运行，语音、模型推理及后台功能可部署在本机或独立服务器。

欣爱是 SynLove 的默认人格，也是桌面控制台里那个会陪着说话的人。

## v2.0 双内核架构

“双内核”指职责与上下文隔离的两个执行角色，不要求两个不同模型，也不意味着每个任务都有一个新的操作系统进程。

1. **主内核（欣爱）**负责日常交流、接待新消息、查询任务状态和整理最终回复。其工具集受限，不加载后台完整操作工具和技能。
2. **执行内核（Worker）**为长任务创建独立 Harness 会话，使用任务提示词和操作工具。用户继续聊天时，后台任务可以继续运行。
3. **结果回传**通过持久任务记录和完成事件交给主人格，再由主人格整理后发送到原通道。整理失败会等待重试，不直接发送 Worker 原始总结。

两个人格可以在 GUI“人格与工具”中分别编辑。默认主提示词为 `prompts/XinAi.md`，执行提示词为 `prompts/TaskExecution.md`；固定执行约束独立保存在 `prompts/WorkerProtocol.md`。用户配置与默认模板分别管理。

任务完成后的主动通知仍受平台权限和会话窗口限制。微信窗口过期后，保存结果不等于能够绕过平台限制主动发送；QQ 也依赖其官方接口状态和额度。

## 功能目录

| 功能 | 使用方式及边界 |

| 微信与 QQ | 双通道接入，分别维护收件去重、消费租约和发送队列；按原通道回复 |
| 人格对话 | 主人格接待、独立执行提示词、后台完成后人格整理 |

| TTS / ASR | 文本转语音、音频上传转写；可调用家庭服务器，主程序不必加载权重 |

| 网页收集 | 公开网页提取，可选浏览器渲染与模型整理 |
| 视频理解 | 音频转写、画面分析、报告及跨机附件传递 |
| 音乐 | 可选本机酷狗 API 与播放控制 |
| 运行观测 | 本机日志、调用链、提示词版本关联、用量和成本趋势 |

定时提醒和爬虫中心共用个人实例对应的后台部署；这类有状态服务需要独立数据目录与凭据。当前不提供共享业务数据库的完整多租户隔离。远程 CMD 是 SSH/FRP 能力，与模型服务的 Hub/Node 转发是两套独立协议。

## 你可以用它做什么

### 日常聊天，也能认真办事

给它发文字、图片或语音，让它查资料、处理文件、整理信息，或者帮你完成多步任务。对话和工具执行由 DeepSeek Harness 承接；需要写代码时，可以把任务交给 OpenCode 或 Codex。

你可以自己写人格提示词，决定它怎样和你说话、怎样处理事情。聊天入口共用后端能力，具体身份和会话隔离按通道配置处理。

### 记住聊天，也记住聊天里的人

长期记忆按日期保存对话与摘要，方便以后查找某一天说过什么。知识图谱则记录人物、关系和相关事实，帮助它理解你提到的人和事。

摘要、图谱抽取等后台处理可以选择本地 Gemma 或云端模型；原始对话、摘要和图谱可以分别维护。你也可以关闭长期记忆写入，或单独决定是否保存模型推理。

### 安排提醒，收集你关心的信息

设置提醒和定时任务，接收新闻摘要，整理视频内容，或者点歌、管理播放队列。相关功能按需要配置，不必一次把所有服务都装齐。

你也可以开启 Codex、OpenCode 的任务完成汇报：任务结束后，将结果整理成自然语言推送 QQ，并注明软件、会话标题和短 ID。新版 OpenCode 按明确的回合结束事件识别结果，工具等待不会被误报成完成；失败或中止也会如实说明。相关设置见 [完成汇报说明](taskReport/README.md)。

微信、QQ 的发送能力仍受各自平台规则限制；任务执行成功与消息送达是两件事，不能保证任何时刻都能主动推送。

### 让欣爱操作你的其他电脑

接入已有 Remote-CMD-Control 的 VPS/FRP 隧道后，可以让欣爱检查指定电脑的连接状态、执行 CMD，并读取真实退出码和命令结果。目标电脑按别名管理，登录凭据保留在本机；不必额外部署一个 SynLove 远控微服务。配置方式见 [远程 CMD](remoteControl/README.md)。

### 按你的设备组合模型和服务

对话模型、故障转移顺序和服务地址都可以配置。TTS、ASR 与本地 LLM 使用独立的服务接口，可以连接本机服务，也可以连接远程服务；本机托管服务支持按需启动。

爬虫中心、网页收集、视频理解和定时任务也可以放在家庭服务器，个人实例通过 API 或 VPS 中转调用。每日新闻归爬虫中心统一维护，后台结果会保存到通知队列，等个人实例接收后再通过现有 QQ 通道发送。旧日程需要先迁移，再切换端点，部署步骤见配套仓库的 `deploy/BusinessDeployment.md`。

主页服务卡片用浅绿表示本机可用、青绿表示远程可用、灰色表示不可用，并附灯色图例；功能是否空闲不影响可用状态。

模型故障转移支持按候选顺序尝试其他模型。使用前需要为相应服务配置有效凭据与额度。

### 用一个清爽的桌面界面查看状态

桌面控制台采用粉白配色、圆角窗口和 16:9 比例，支持托盘驻留。完整启动程序时会播放开屏视频，播完淡出进入界面；从托盘恢复或取消最小化时，离开满一小时才再次播放。三段开屏按 1 → 2 → 3 顺序轮换，重启后也会接着上次的顺序。

你可以在里面：

- 查看后端可用状态、消息通道、最近动态和定时任务。
- 切换默认模型、管理工具、编辑人格和调整记忆参数。
- 查看发送队列、后台守护、日志和 Token 用量。
- 在调用链中检查模型、工具及通路片段，在运行趋势中比较耗时、错误率和成本估算。

功能卡片按每页 5 项翻页，顺序固定，不会因为服务数量变化把页面越撑越长。绿灯表示服务当前**可用**，不是“正在被调用”：TTS、ASR 和本地大模型按需启动，空闲时显示“按需待机”，接到请求会自己拉起。卡片会定期发送轻量心跳，协议校验失败或依赖缺失时转为灰灯。

参数与工具名称旁的小问号会显示说明。历史探针也可以补录为运行统计，但缺失的会话关联、工具结果和版本信息会明确标注。

## 开始使用

目前主要面向 **Windows 桌面环境**。先安装 Python 3.9+ 和 Node.js 24 LTS，然后下载本仓库，双击根目录的 **Start.cmd**。

首次启动自动创建隔离 Python 环境、安装后端与桌面依赖、生成配置，并加载默认的欣爱人格。后端运行代码已经包含在 `backend/`，不需要另行克隆 DeepSeek Harness，不需要 pnpm 或编译 TypeScript。启动器会先确认 Harness 和微信/QQ接入，再在后台预热提醒、摘要、OpenCode、RSSHub 等可选服务；可选服务失败不会阻塞消息通道。

进入桌面后，配置模型密钥并绑定微信，再从“系统”启动后端；也可以额外接入 QQ 官方机器人。需要更换接口与模型时编辑 `config/modelConfig.json`；密钥放在 `config/secrets.json`。

安装完成后可运行 `autostart.ps1`，一次性创建桌面、开始菜单和开机自启入口。桌面快捷键是 **Ctrl+Alt+S**；开机自启只保留一个 SynLove 入口并默认驻留托盘，所有入口都会经过同一个启动协调器，不会重复拉起第二个 Harness 消费者。右击托盘图标可选择“重启 Agent 内核”或“停止系统并退出”。

只安装而不打开窗口：`python bootstrap.py --install-only`。检查发行文件：`python bootstrap.py --check`。

TTS、ASR 和 LLM 的地址在 `config/serviceConfig.json` 中配置。本机托管使用 `managed`，自行运行或远程部署的服务使用 `external`；模型权重和服务端依赖需要另外安装。远程公共能力由配套仓库 `SynLove-Backend-Service` 提供，本仓库只保留个人实例的消息通道、记忆、会话、状态、日志、调用链和本地编码器。

GUI 的“通道 → 远程连接”页面可以选择本机或远程后台服务，填写地址、协议与 API 密钥，并按默认端口前后递推查验。只有通过对应服务身份协议的接口才会连接；普通占用端口或无响应端口会继续查找。此页也可以添加远控电脑、核对 SSH 主机指纹并测试 CMD 通信。主页的“远程连接”卡片可直接进入配置页，远控状态以最近一次实际测试结果为准。

## 统一微服务链路

提醒、新闻摘要、视频处理、爬虫、记忆、微信状态、QQ 状态、观测和 Harness Session 都有独立的服务边界。上层通过统一 HTTP/MCP 请求访问它们，服务的地址、端口、超时、鉴权和生命周期集中写在 `config/serviceConfig.json`。本机部署时两套仓库可以放在同一台机器；远程部署时只需把公共服务的地址切换到 `SynLove-Backend-Service` 所在服务器，个人数据仍留在本机。

服务只维护自己的状态库。微信和 QQ 分别使用自己的租约、入站状态与发送队列；重复请求使用稳定消息指纹幂等，两个通道同时发送不会共享序号或互相覆盖。`managed` 服务由启动器负责拉起和关闭，`external` 服务只探活、不在本机偷偷补拉，端口被未知进程占用时直接报错，不创建第二个消费者。

## 稳定性验证

发行包在隔离临时目录中完成了 65 项链路测试，覆盖微信/QQ 双端并发重复发送、多实例租约竞争、服务重启恢复、重复请求幂等、并发上限、Worker 超时与输出上限、跨域关闭防护、爬虫私网地址拦截、远程 ASR/TTS 上传边界、提醒/新闻/视频服务以及 Harness Session 远程持久化。控制台另有 24 项前端与探活测试，覆盖服务卡分页、按需服务判定、Codex/OpenCode 连接器和心跳状态。测试不会连接真实微信、QQ、模型账号或生产数据库。

语音、音乐与本地模型均为可选服务，不影响先使用云端模型聊天：

| 服务 | 安装与启动 |
| --- | --- |
| ASR 语音转写 | `python service.py asr`，首次转写自动下载模型 |
| TTS 语音合成 | `python service.py tts --python <Python3.12路径> --download-model` |
| 本地 LLM | `python service.py llm --download-model`，默认 CPU 引擎 |
| 酷狗音乐 API | `python service.py kugou` |

只看安装计划可加 `--plan`，只安装不运行可加 `--install-only`。TTS、LLM 权重较大，只有加上 `--download-model` 才主动下载；已有远程接口时直接改服务地址即可。TTS 和音乐首次安装还需要 Git。

各项可选功能需要对应环境、权限和账号。建议先验证单个聊天通道，再逐项启用记忆、语音、远控和编程工具。

### 后台功能拆分版

- 四项业务实现加入 Backend，个人实例保留 API/MCP 接入、个人数据和消息发送。
- 新闻摘要与每日新闻并入爬虫中心；网页收集增加隔离浏览器与 Gemma 整理。
- 增加后台结果持久保存、本机拉取确认、原有 QQ 队列去重及旧日程迁移工具。
- 服务卡片区分本机和远程绿灯，新增图例，健康检查失败或依赖缺失显示灰灯。
- 支持接口不代表远端已部署，实际切换前必须通过功能协议和迁移收据校验。

### 远程连接与新闻状态修复版

- 新增“通道 → 远程连接”，集中配置本机或远程后台服务，以及通过已有 SSH/FRP 隧道访问的其他电脑；主页同步增加入口。
- 支持后台 API 密钥、远控登录密码与主机指纹校验；凭据只保存在本机，保存后不回显。远控工具可检查连接、执行 CMD 并返回退出码，超时不会自动重试命令。
- 新闻定时卡片读取新闻服务的真实调度状态，修复旧 Windows 计划任务已停用时误显示“停用”的问题。
- 通过 28 项控制台测试、22 项远控测试、14 项微服务测试、4 项启动测试及浏览器操作验证；隔离验证不代表已经连接真实远控电脑。
