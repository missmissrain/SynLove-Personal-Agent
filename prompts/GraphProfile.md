【附加任务：维护“主人”的画像（不影响上面的事实抽取）】

先严格按上面的抽取规则输出人物、属性、关系、事件，一条都不能少。
在这个基础上，如果本块对话能推断出主人的兴趣、偏好、目标、处境或沟通方式，再额外输出画像行。

画像是从行为里推断出的结论，不是把问题原样抄一遍。事实只是证据。
- 他问过怎么去伊斯坦布尔、比较春节机票 → 画像写“兴趣：土耳其/欧洲旅行，正在计划春节出行”，不要抄航班问题。
- 他反复问显卡价格、对比 3090 和 3060、看租卡平台 → 画像写“目标：配置一台本地 AI 机器；消费观：预算敏感，倾向二手”，不要罗列型号和价格。

【画像格式】
只写“主人”一个人。标签开头，用中文分号“；”连接成一行：
兴趣 / 偏好 / 厌恶 / 沟通 / 习惯 / 目标 / 计划 / 处境 / 消费观 / 技术取向 / 作息

【证据标记】
- 主人明确说过的，直接写结论。
- 从多次行为推断出来的，结论前加【推断】。
- 只出现一次、又没有其他佐证的，不写；确实值得留的写“关注：…”，不要升级成长期偏好。

【硬性规则】
1. 画像是“人”的特征，不写对助手的工作要求、操作规范、任务流程、工具约定（这些属于系统规则，不是画像）。
2. 作息只有主人明确说过才写，格式“作息：睡眠 23:30-08:00；上班 09:00-18:00；午休 12:00-13:00”；没说过就不写。
3. 只推断行为倾向、兴趣、目标、处境和沟通方式；不推断健康、政治、宗教、性取向、身份，不做人格诊断，也不做负面评价（如冲动、拖延、健忘）。
4. 不写网址、文件名、文件大小、权重清单、命令、密钥这类执行细节。
5. 不写没出现过的具体型号、金额、日期；计划必须带日期，过期的改成“过去关注：…”。
6. 现有备注如果是流水账、原始事实或操作规范，要改写成画像结论或直接删掉；仍然成立的旧条目保留。
7. 助手自己的建议、承诺、猜测不是主人的画像，除非主人明确确认。
8. 同一标签只保留一条；新证据推翻旧结论就替换，互不冲突的标签都要保留。

【输出协议】
- 抽取阶段：在正常事实行之外，额外输出画像行 `属性|主人|备注|<画像>`。
- 审核阶段：只输出 `更新|备注|<合并后的完整画像>` 一行，多类用“；”连接，不要换行。
- 本块没有可用于画像的信息时，不要输出画像行，也不要输出“无”，更不能因此省略其他事实。
- 除协议行外不输出解释，不回复用户，不模仿主人格聊天。
